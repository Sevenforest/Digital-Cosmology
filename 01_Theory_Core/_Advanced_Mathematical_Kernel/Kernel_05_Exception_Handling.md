## 2. Saturation of Algorithmic Load (演算分岐負荷の飽和)

### 2.1 Decoupling from Gravitational Energy Density ($T_{\mu\nu}$)
`Kernel_02` のエネルギー・運動量テンソル $T_{\mu\nu}$ は空間ドメインの重力スロットリングを規定するマクロな「エネルギー・質量密度」である。これに対し、ソフトエラーの引き金となるのは単なる物質密度ではなく、**局所因果領域におけるアルゴリズム的非圧縮性・状態分岐の競合密度（計算負荷率 $\rho_{\text{op}}$）**である。

$$0 \le \rho_{\text{op}} \le \rho_{\max}$$

* $\rho_{\max}$: 実行基底（Execution Substrate）が局所処理プロセスへ割り当て可能な最大スループット上限。
* **重力密度との違い:** 恒星内部や中性子星のようにエネルギー密度 $T_{\mu\nu}$ が極めて高い領域であっても、統計的に一様な熱平衡状態にある部分はマクロな統計近似で低コストに圧縮処理でき、論理分岐負荷 $\rho_{\text{op}}$ は必ずしも飽和しない。逆に、非平衡かつ高密度な再帰フィードバック・状態分岐が集中する領域（あるいは高エネルギー極限の不安定遷移点）では、エネルギー規模の大小に関わらず $\rho_{\text{op}} \to \rho_{\max}$ に近づく。

### 2.2 Headless Universality (非特権の原則)
宇宙OSのカーネル側に「脳」や「生命」を識別する特別なプロセスIDは存在しない。高密度な非平衡物理現象であれ、複雑な化学反応ネットワークであれ、生物の神経回路や高度な計算システムであれ、**局所的な状態分岐負荷が上限 $\rho_{\max}$ 近傍へ飽和した任意の物理領域**において、同一の法則でソフトエラーが発生する。

## 3. Mechanism of Soft Errors (ソフトエラーの発生と保存則の両立)

### 3.1 Fault Generation at Quantization Boundary
`Kernel_03` (2章) で定義された通り、システムは有限ビット解像度に基づく丸め込み境界を持つ。通常の低負荷状態（$\rho_{\text{op}} \ll \rho_{\max}$）では丸め込みは規則通りに処理されるが、局所負荷が限界へ飽和（$\rho_{\text{op}} \to \rho_{\max}$）すると判定マージンが消失し、**非決定的なビット反転（ソフトエラー）**が発生する。

### 3.2 Error Rate Formulation (エラーレートの近似スケッチ)
局所スカラー負荷率 $\rho_{\text{op}} \in [0, \rho_{\max}]$ に対するソフトエラー発生確率 $P_{\text{error}} \in (0, 1]$ の近似挙動は、飽和点からの余裕度に応じて指数関数的に急増する関数として記述される。

$$P_{\text{error}} = P_0 \exp\left( \frac{\rho_{\text{op}} - \rho_{\max}}{\sigma} \right) \qquad (0 < P_0 \le 1, \quad \sigma > 0)$$

* $\sigma$: ハードウェアの耐障害マージン幅。
* $\rho_{\text{op}} \ll \rho_{\max}$ の低分岐・定常領域では $P_{\text{error}} \approx 0$ となり、系はほぼ完全に決定論的カオスと規則的丸め込みに従う。
* $\rho_{\text{op}} \to \rho_{\max}$ の飽和領域では $P_{\text{error}}$ が無視できない値へ立ち上がり、因果グラフ（DAG）に完全決定論からは一意に定まらない新規分岐を割り込ませる。

### 3.3 Energy Shell Compliance (総エネルギー殻保存の厳守)
このソフトエラーは「無からエネルギーを創造する奇跡」ではない。遷移自体は `Kernel_01` (3.1節) の絶対制約である **エネルギー殻の閉包則 $F(S_E) \subseteq S_E$** の内部で発生する。
すなわち、ソフトエラーによって起きるのは「別の総エネルギー殻 $S_{E'}$ への逸脱」ではなく、**同一の総エネルギー $E = (E_{\text{baryon}} + E_{\text{index}}) + E_{\text{rad}} = \text{const.}$ を保ったまま（必要に応じ局所的な排熱セクタとの微小なエネルギー再配分を伴い）、遷移先の状態分岐が非決定的に反転する**現象である。

## 4. Physical Commit, Amplification, and Recall (物理的確定・増幅回路・想起の分離)

`Vol.2` (3.2節・5章) のヘッドレス実行原則および `Vol.3` の設計通り、**意識（Log Reader）自体は物理ログへの直接の書き込み権限（Write Access）を持たない**。ソフトエラーがマクロな現実の分岐として確定する過程は、以下の完全ヘッドレスな物理プロセスとして記述される。

### 4.1 Local Dirty State & Amplification Circuit (増幅構造の差)
任意の飽和領域で生じたソフトエラーは、当初はミクロな未確定状態（ローカルな Dirty State ※`Kernel_04` の広域空間インデックスの Dirty Cache とは別レイヤー）に留まる。
通常の無秩序な非平衡系（プラズマ乱流や気象現象等）で生じた単発のソフトエラーの大半は、周囲の熱ノイズへ即座に吸収・平均化されて消滅する。これに対し、**生物の神経系や高次情報処理システムは、単発の微小発火をカスケード的にマクロな運動出力・物理的相互作用（Write）へと増幅する回路構造**を進化的に備えている。この物理的な増幅構造の違いによってのみ、生命システムにおけるソフトエラーは現実の行動分岐（いわゆる自由意志）として顕在化しやすくなる。

### 4.2 Race Condition & Physical Commit (競合と確定)
エラー発生直後、システム側には局所的な不整合を減衰させて元の決定論的軌道へ戻そうとする復元傾向（熱的ノイズへの埋没）が働く。

* **The Conflict:** 「システムによるエラー減衰（熱的・決定論的慣性）」 vs 「増幅回路によるマクロ相互作用への波及・Commit」。

この競合（Race Condition）を勝ち抜いて周囲の環境と不可逆な状態確定（Physical Commit）を完了したソフトエラーのみが、因果グラフ（DAG）上の変更不能な事実としてマージされる。

### 4.3 Integration via Recall (Read)
意識（`Vol.1`・`Vol.5` の UI層）は、物理的 Commit によって確定済みのログを「想起（Recall）」として事後的に読み出し（Read）、自己の歴史物語へと統合する。我々が「自分の意志で選択した」と感じるクオリアは、非特権的な物理ハードウェアが起こした非決定的分岐とその増幅・物理的確定のログを、意識層がリアルタイムに近い遅延で解釈した結果である。
